## 1. Executive Summary

The **Vitality** backend core is **Substantially Complete** regarding the primary hackathon goals: Multi-hospital coordination, dynamic triage, and simulation capabilities are fully functional. The system successfully implements the decentralized execution model with a centralized orchestrator.

However, several "Advanced" or "Policy" features described in the PRD (Policy-as-Code, explicit Human-in-the-Loop workflows, and Doctor Fatigue modeling) are either simplified or currently missing.

## 2. Component Analysis

### 2.1 Core Triage & Scheduling (✅ Implemented)
- **Priority Logic:** Fully implemented in `Patient.java`.
  - Formula: `BaseSeverity + (WaitTime * Factor) + DistressScore`.
  - matches PRD "Fairness aging".
- **Concurrency:** Implemented via `PriorityBlockingQueue` and `ThreadPoolExecutor` in `HospitalService.java`.
- **Departments:** Nurse, General, and ICU tiers are modeled with referral logic.

### 2.2 Multi-Hospital Coordination (✅ Implemented)
- **Orchestrator:** `OrchestratorService.java` runs a scheduled task (`fixedRate = 7000ms`) to monitor queues.
- **Redirection:** `evaluateRedirection` logic considers queue size and distance penalty.
- **Transfers:** `transferPatient` safely moves patients between hospital queues.

### 2.3 Surge Detection (✅ Implemented)
- **Logic:** `SurgeDetectorService.java` uses a sliding window (Deque) to track arrival rates.
- **Response:** Automatically toggles "Survival Mode" (adjusting `Patient.AGING_FACTOR`) when threshold (10/min) is breached.

### 2.4 Real-Time Communication (✅ Implemented)
- **WebSockets & SSE:** Both implemented via `WebSocketService` and `SseController`.
- **Events:** Broadcasts System Init, Patient Admit, Treatment Start/End, Surge, and Distress events.

### 2.5 Simulation Engine (✅ Implemented)
- **Control:** `SimulationController` exposes endpoints to:
  - Initialize City (`/init`)
  - Inject Patients (`/patient`)
  - Trigger Artificial Surges (`/surge`)
  - Simulate Staff Shortages (`/staffing/shortage`)

## 3. Gaps & Missing Features (vs PRD)

### 3.1 Policy-as-Code (❌ Missing)
- **PRD Req:** YAML-based configuration (`triagePolicy`) and dynamic reload via API.
- **Current State:** Logic is hardcoded (e.g., `AGING_FACTOR`, `SURGE_THRESHOLD`). No `PolicyService` or configuration loader found.

### 3.2 Human-in-the-Loop / Nurse Confirmation (⚠️ Partial)
- **PRD Req:** Explicit confirmation workflow (`POST /patients/{id}/update` with source `NURSE_CONFIRMATION`) to validate distress/redirection.
- **Current State:** `SimulationController` has `/distress` endpoint to boost priority, but it acts as a direct data ingestion point rather than a "Review & Confirm" workflow.

### 3.3 Doctor Fatigue & Efficiency (❌ Missing)
- **PRD Req:** Fatigue cooldowns and temporary efficiency reduction.
- **Current State:** `treatPatient` sleeps for a fixed duration (`TREATMENT_TIME_MS`). No fatigue state tracking for individual doctor threads.

### 3.4 Explicit Redirection States (⚠️ Simplified)
- **PRD Req:** `SAFE`, `CONDITIONAL`, `NO_REDIRECT` states with explainability.
- **Current State:** Binary decision (Move or Stay). "Explainability" is limited to a `benefitScore` in the log/broadcast.
